# 详细设计

本文档记录当前实现的关键设计，便于后续手工修改和代码回看。

## 1. 后台 shell

### 结构

- 左侧：固定导航菜单。
- 顶部：固定页头，放站点标题、语言切换和退出按钮。
- 右侧：独立滚动区，只滚动内容，不滚动导航和页头。

### 设计原因

后台长期使用时，导航和上下文不能随内容滚动消失，否则编辑文章和查看仓库时会反复丢失位置。

## 2. 文章管理

- 文章列表采用表格。
- 新建和编辑都使用居中的大弹窗，不使用右侧抽屉。
- 编辑表单保留 Markdown 原文，避免长文内容在窄侧栏里被压缩。
- 列表里的标题、状态和更新时间都做了紧凑展示。

## 3. 站点页与 JSON 资源

- Markdown 资源使用左右分栏。
- 左侧是原文编辑区，右侧是 HTML 预览区。
- JSON 资源左侧是编辑区，右侧是格式化预览区。

## 4. 资源仓库

![资源浏览布局](assets/admin-shell.svg)

资源浏览采用“目录列表 + 文件预览”模式：

- 左侧显示当前目录文件。
- 点击目录进入下一层。
- 点击文本文件，在右侧显示原文。
- 点击图片文件，在右侧显示图片。

实现上统一通过 `/admin/repository/file` 获取预览，避免前端自己猜文件类型。

## 5. 版本控制

- 使用 `/admin/repository/status/details` 获取结构化变更。
- 变更列表可点击，右侧显示选中文件预览。
- 提交、抓取、拉取分别作为独立操作。
- 不直接只展示一段 `git status` 文本，便于快速看懂变动。

## 6. 代码约定

- 默认中文界面。
- 面向维护者的说明文字尽量短。
- 只有结构复杂的区域才加中文注释。
- 文件组织遵循 `src/` 与 `docs/` 分层，不把源码和文档混在根目录。
